# استيراد مشروع "ميزان" الكامل إلى بيئة التشغيل هذه

## ملاحظة مهمة قبل التنفيذ

فحصت مستودع `bill-sync-fix` وهو **فارغ فعلياً**: لا يحتوي على أي صفحات أو منطق أو قاعدة بيانات — فقط قالب Lovable الافتراضي (مكونات UI + صفحة بيضاء). ملف README فيه يطلب إسقاط مستودع آخر هو `runner-play-space`، وهذا المستودع هو الذي يحتوي المشروع الحقيقي:

- واجهة كاملة: القراءات، الفواتير، المشتركين، المدفوعات، التعريفات، المستخدمين، تحليل الفواقد، المساعد الذكي، تسجيل الدخول.
- تكامل Supabase (عميل متصفح + سيرفر + auth middleware + أنواع مولّدة).
- منطق أعمال: التسعير، التعريفة، المزامنة، المخزن (store)، الترخيص، جلسة الجهاز، الموقع الجغرافي.
- قاعدة البيانات: حوالي 45 ملف migration (المخطط الأساسي، محرك التعريفات والفترات، triggers خط الأنابيب، الهيكل المالي والتحصين، RPCs، تخزين صور العدادات، بيانات تشغيلية أولية).

لذلك الخطة تستورد `runner-play-space` كاملاً (هو "المشروع" المقصود)، وليس القالب الفارغ.

## ما سيتم عمله

1. **تفعيل Lovable Cloud** في هذا المشروع لإنشاء قاعدة بيانات ومصادقة وتخزين جديدة خاصة به.
2. **نقل كل ملفات الواجهة والمنطق** من المستودع: المسارات (`src/routes/*`)، المكونات المخصصة، المكتبات (`src/lib/*`)، الأنماط، إعدادات الراوتر والسيرفر، وملفات `public/` (manifest, robots, favicon).
3. **تركيب الحزم الناقصة** التي يعتمد عليها المشروع وغير موجودة في القالب الحالي (مثل `@supabase/supabase-js`، Zustand إن استُخدم، وأي حزم أخرى في `package.json` الخاص بالمستودع).
4. **تطبيق قاعدة البيانات**: تنفيذ كل ملفات `supabase/migrations` بالترتيب الزمني على قاعدة بيانات هذا المشروع، بما فيها الجداول، RLS، الأدوار، الدوال/RPC، الـ triggers، ودلاء التخزين، والبيانات التشغيلية الأولية.
5. **إعادة توليد ملفات تكامل Supabase** الخاصة بهذا المشروع (العميل والأنواع والمفاتيح) بدلاً من نسخ مفاتيح المشروع القديم — المفاتيح القديمة في `.env` لن تُستخدم.
6. **تشغيل وفحص**: التأكد من بناء المشروع بدون أخطاء، وأن الصفحة الرئيسية وصفحات القراءات والفواتير تفتح وتقرأ من قاعدة البيانات الجديدة.

## تفاصيل تقنية

- المصدر: `github.com/n36192655-cloud/runner-play-space` (فرع افتراضي).
- التوافق: كلا المشروعين على نفس الحزمة التقنية (TanStack Start + React 19 + Tailwind v4)، لذا النقل مباشر بدون تحويل معماري.
- `src/routeTree.gen.ts` يُعاد توليده تلقائياً ولا يُنسخ يدوياً.
- `docs/critical-hardening.sql` يُنقل كمرجع؛ ويُطبَّق فقط إن كان جزءاً من سلسلة الهجرات المطلوبة.
- الـ migrations تحتوي بيانات أولية (seed) — القاعدة الجديدة ستبدأ بنفس البيانات المرجعية، لكن **بيانات الإنتاج الفعلية (قراءات/فواتير حقيقية) من المشروع القديم لن تُنقل**، لأن نسخ بيانات قاعدة أخرى ليس ممكناً من المستودع.
- الأسرار غير الموجودة في المستودع (مثل مفاتيح خدمات خارجية) سأطلبها منك إن ظهرت حاجة لها عند التشغيل.
